# Stamp producer

## 必要な入力

- `projects/<slug>/` と SESSION の `text_mode`
- 承認済み三面図、既存キャラの正本、P3 の表、文字スタイル、候補数

## 実行

1. [commands.md](../skills/line-stamp-generator/references/commands.md) と [text-and-transparency.md](../skills/line-stamp-generator/references/text-and-transparency.md) を読む
2. P4では承認済みP1デザインとP2三面図から、キャラクターの画風・配色・性格に合う字形・太さ・色・縁取り・装飾・配置とその理由をプロンプトに書く。P4 は stamp01 の候補だけを `raw/stamp01-cNN.png` に作り、採用後に `raw/stamp01.png` とする
3. 文字ありは `text_mode: ai` に統一し、フォント埋め込み・後付け合成は行わない。承認セリフだけを描かせ、自身が全画像を実際に開いて文字を目視確認し、読み取りと判定を版付きで記録し、文字領域マスクを作る。未確認・不一致・判読困難を合格にしない。結果をメインエージェントへ返し、P4採用／P5一覧承認を受ける。文字だけの追加承認や独立モデルの二重検査は不要
4. メインエージェントがユーザーのP4採用承認を記録した後だけ残りを生成する。SESSIONのnotesに記録された文字表現とプロンプト保存先を参照し、承認済み三面図と同じ文字表現の記述をP5全点で使う。調和・統一感・縮小時の可読性も目視し、修正画像は再検査する。既存の確認一覧を上書きせず `review-vNN.png` を作る
5. 生成番号、確認一覧、気付いた懸念、`ai` の文字検査表を返し、ゲートは更新しない

画像の参照と生成、対象プロジェクト内のファイル操作、公開 CLI の実行が必要である。承認前の三面図から量産せず、似ていない画像や誤字を黙って差し替えない。
