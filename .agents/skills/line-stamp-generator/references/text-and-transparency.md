# AI文字と透過の処理

## 文字方式

P0では文字の有無を確認し、文字ありは `text_mode: ai`、文字なしは `text_mode: none` と記録する。方式の選択質問はしない。文字ありは生成AIによる描画のみとし、フォント埋め込み・後付け合成は行わない。確認一覧の番号・版など、提出スタンプに含まれない管理用ラベルの描画はこの制限の対象外とする。

| 方式 | 画像 | 検査 |
|---|---|---|
| `ai` | 生成AIがキャラクターと文字を描いた画像 | 生成AIの目視確認記録＋P4採用／P5一覧承認、文字領域マスク |
| `none` | 文字なしのキャラクター画像 | P4/P5で意味・同一性・透過・余白を目視 |

旧 `font` 案件は画像や承認記録をそのまま保存する。AI描画済みへの自動変換は行わず、移行・制作・梱包・公開前検証を停止し、新しいai案件で通常のゲートを経た再制作を案内する。

## キャラクターに合わせる文字スタイル

P4候補では承認済みP1デザインとP2三面図から、キャラクターの画風・配色・性格に合う文字表現を提案する。全キャラへ一律の文字スタイルを適用しない。生成プロンプトには次を具体的に書き、候補と一緒に示す。

- 字形の雰囲気（丸み、角ばり、手描き感など）と線の太さ
- 塗り色と縁取り色（承認済み配色に調和するHEX値）
- 装飾の種類・量と、文字の配置・行数
- キャラクターのどの特徴に合う表現か、その理由
- 承認済みセリフを一字一句そのまま記した文字列

縁取りは文字と同心に描く。斜めや下方向へずらした複製、ぼかし、グローは影なので使わない。装飾が字形を崩したり、顔や表情を隠したりしないようにする。

P4の候補採用と同時に文字表現の承認を得る。メインエージェントがSESSIONのnotesに採用内容とプロンプト保存先を記録する。P5では同じ記述と承認済み三面図を全点の生成に参照する。セリフ・表情・ポーズに応じて配置を調整しても、字形・色・太さは採用した表現を維持する。文字だけの追加承認ゲートは設けない。

以下は提案の例であり、実案件では承認済みキャラクターの特徴・配色に置き換える。

| 承認済みキャラクターの例 | P4で提案する文字表現の例 |
|---|---|
| クリーム色と茶色の、丸く穏やかなキャラ | 丸みのある柔らかな手描き文字。中太、塗り #FFF1CC・同心の縁取り #6B4E32、装飾なし、顔の上に読みやすく配置。丸い輪郭と温かな配色に合わせる |
| 濃紺とオレンジの、元気なキャラ | 太く動きのある手描き文字。塗り #FF9F43・同心の縁取り #243B53、小さな動き線を文字外へ配置、表情を隠さない上部配置。活発なポーズと強い配色に合わせる |

プロンプト保存内容の例:

```text
参照: 現在の承認済みP1デザイン、P2三面図。
文字表現: P4で採用した字形・太さ・HEX色・縁取り・装飾・配置の記述をここへそのまま入れる。
キャラクターに合う理由: 採用した理由をここへ入れる。
セリフ: 「承認済みセリフ」
文字は正確に、この文字列のみ。キャラクターと文字を生成AIで描く。
承認済みキャラクターの顔・体形・配色を維持する。顔を隠さず、縮小しても読める文字にする。
```

## 画像処理と透過

生成結果、前処理した画像、キャンバス上のレイヤー、最終スタンプを分けて保存する。aiの文字は生成画像に含まれるため、文字専用レイヤーは作らない。`character-layers` という内部名の画像も、aiでは文字を含む。noneでも前処理・合成・確認一覧・梱包・検証は省略しない。

aiでは `preprocess-character --no-fill-holes` を使い、`compose-static` の穴補正は行わない。文字のカウンターや自然な抜きを白で埋めない。noneの微小穴補正はキャラクターレイヤーだけへ適用する。最終合成画像へ穴埋め処理をしない。

白縁はalphaを膨張させた後、拡張キャンバス端につながる外側の透明領域だけへ合成する。キャラクターと文字を含む可視内容に上下左右12px以上、目標16pxの余白を確保し、不足時は縮小する。低アルファ画素のRGBAをゼロに正規化し、アンチエイリアスの半透明画素は残す。

`verify-text` が最終画像と同寸法の版付き文字領域マスクを作る。`validate-pack --text-mode ai` はマスク内に完全に収まる文字カウンターだけを除外し、文字領域外の微小穴を検査する。マスクは文字だけを囲み、キャラクターへ重ねない。欠落・ハッシュ不一致・過大なマスクを合格にしない。

## レビュー

P4/P5では生成AIが各最終画像を実際に開き、承認セリフとの一致・誤字・脱字・鏡文字・字形崩れ・判読困難を確認する。版付きの目視記録を保存し、未確認・不一致・判読困難を合格にしない。全点一致とP5一覧承認後に `text_check: ok` を記録する。文字だけの追加ユーザー検査や独立モデルの二重検査は不要である。

キャラクターとの調和、全点の統一感、縮小時の可読性も確認する。白系・濃色背景の全点一覧で、文字周辺の白い島、薄い矩形、影、ギザギザ、キャラクターの欠けを見る。問題のある番号だけ再生成し、修正画像の文字検査と一覧確認をやり直す。文字表現自体を変える場合はP4へ戻して承認を得る。

確認一覧は `review-v01.png`、`review-v02.png` と版を上げ、上書きしない。パイプラインは `preprocess-character` → `compose-static` →（aiのみ `verify-text`）→ `make-contact-sheet` → `package-static` → `validate-pack` の順に実行する。`publish: yes` でP7へ進む場合だけ、続けて `check-publish-ready` を実行する。具体的なコマンドは [commands.md](commands.md) を参照する。
