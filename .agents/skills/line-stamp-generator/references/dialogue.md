# 対話の進め方

## 原則

- 1ターンに1論点。複数聞くときは番号付きで最大3問まで
- 選択式にできる質問は選択肢を示し、既定値を明記する（例: 「枚数は 8 / 16 / 24 / 32 / 40。初回は16がおすすめ」）
- 実行環境に構造化された選択 UI があれば使う。なければ番号付き選択肢を文章で示す。特定製品のツール名を共通手順へ持ち込まない
- 回答を受けたら、その時点で確定した内容を3〜6行で復唱し、次のゲートへ進む前に「この内容で進めます。修正があれば今のうちに」と一言添える
- 曖昧な回答（「いい感じで」「おまかせ」）は、こちらの提案を1案だけ示して承認を取る。黙って決めない
- 承認語: 「OK」「続けて」「いいね」「それで」。差し戻し語: 「違う」「戻して」「もっと〜」。判別できなければ「承認として進めてよいですか」と確認する
- 差し戻しでは何が違うかを1問で特定し（顔・髪・服・ポーズ・文字のどれか）、該当ゲートだけをやり直す
- 生成画像は必ず「何を確認してほしいか」を添えて出す（例: 「前髪の分け目と目の大きさを見てください」）
- 素材の権利不明または写真の本人許諾なしが分かった時点で制作を止める。権利と許諾が確認済みでも成年が `no|unknown` の場合は、ローカル確認用成果物（LINE 上で配布・利用不可）だけを案内する

## プロジェクト確定の質問テンプレ

制作依頼を受けたら P0 より前に確定する。`python scripts/line_stamp.py project --root . list` の結果に進行中があれば:

```text
進行中のプロジェクトがあります。どうしますか？
1. usagi（P4 / 16枚 / 未申請）を続ける
2. neko（P7 / 8枚 / メタ案待ち）を続ける
3. 新しいプロジェクトを作る
```

新規作成を選んだら、実名でない slug を確定して公開 CLI の `project ... new --slug <slug>` で P0 プロジェクトを作る。素材はその `refs/` に置き、P0 の全項目をユーザーが承認した後だけ `project ... confirm-p0` を実行する。`confirm-p0` が確定内容を SESSION へ保存し、P1 へ進める。

## P0 の質問テンプレ

```text
LINEスタンプの制作を始めます。3つ教えてください。
1. 元にする素材はどちらですか？
   A. 人物の写真（ちびキャラに変換します）
   B. 既存のキャラクター画像（そのデザインを踏襲します）
2. 枚数はいくつにしますか？ LINEの規定で 8 / 16 / 24 / 32 / 40 のいずれかです。初めてなら16をおすすめします。
3. スタンプに文字（セリフ）を入れますか？ 入れる / 入れない
```

文字を入れる場合は続けて方式を選択肢で聞く:

```text
文字の入れ方を選んでください。
A. 埋め込みフォント（おすすめ）— 承認したセリフから決定論的に描き、全点で同じ見た目にします。原文、欠字、可読性は確認一覧で目視します
B. 生成AIに描かせる — 手書き風など自由な表現ができます。ただし誤字や字の崩れが出やすいので、1点ずつ文字の検査と確認をはさみます
```

続けて（未確定のものだけ）:

```text
4. キャラクターの呼び名を決めてください（申請時のタイトルにも使います。実名は避けます）
5. LINE Creators Market へ審査申請しますか？ する / しない（ローカル確認用の成果物まで。LINE 上では配布・利用できません）
   →どちらの素材でも: 写真・イラスト素材とキャラクターの著作権・商用利用権は、ご自身の保有ですか／明示的なライセンスがありますか？ 不明なら制作を開始できません
   →人物写真の場合: 写っているご本人の制作許諾はありますか？ 本人の申告として成年ですか？ 外見からは判定しません。許諾なしは制作不可、未成年・不明はローカル確認用のみです
   →既存キャラの場合: ご自身が権利を持つオリジナル、または商用利用を明示的に許諾されたオリジナルですか？
6. 代表スタンプ（01）の候補を何枚出しますか？ 1 / 2 / 3（既定1）
```

## 各ゲートの提示と質問

| Gate | 提示するもの | 聞くこと |
|---|---|---|
| P1 | 特徴ロック（3〜6行）またはデザインシート | 「残す特徴・外す特徴はこれで合っていますか」 |
| P2 | 三面図1枚（正面・斜め・決めポーズ） | 「3つが同じキャラに見えますか。違和感は 顔 / 髪 / 服 / 体型 のどれですか」 |
| P3 | セリフ・表情・ポーズ表（agentが枚数分を提案） | 「差し替えたい番号と新しいセリフを教えてください。なければOKで確定」 |
| P4 | stamp01の候補と文字スタイル（`font`: フォント・色・縁取り／`ai`: 文字の雰囲気）。`ai` は 01 の文字検査結果 | 「採用する候補番号」「文字の色と縁取りはこのままで良いか」。`ai` は「読み取った文字は『◯◯』です。承認セリフと一致していますか」 |
| P5 | review-vNN.png（白背景と濃色背景）。`ai` は text-check-vNN.md と読み取り表 | 「修正したい番号を教えてください。なければOKで梱包に進みます」。`ai` は先に「文字が正しくない番号はありますか」を 全点正しい / 誤字あり（番号）で聞く |
| P6 | 検証ログとZIPのファイル一覧 | 質問なし。エラー0を報告してターンを終了し、P7 は次のターンで開始 |
| P7 | メタ案（日英タイトル・説明、クリエイター名、コピーライト、価格、3択の販売エリアと対象国、手動販売開始、LINE STORE 表示、AI/写真使用申告、ライセンス証明、プレミアム参加） | 「この内容で登録して良いですか。変更箇所があれば項目名で」 |
| P8 | Creators Market に入力した内容のサマリと画面確認結果 | 「内容と同意事項を確認し、『同意します』の選択と『審査をリクエスト』をご自身で行ってください。完了したら教えてください」 |
| P9 | 審査状況 | 承認時: 「リリースボタンを押すと販売開始です」／却下時: 「理由は◯◯です。P◯からやり直します」 |

## 文字検査の出し方（`text_mode: ai` のみ、P4 と P5）

1. 公開 CLI の `verify-text` を実行し `review/text-check-vNN.md` を作る
2. エージェント自身が各画像を開いて文字を読み、次の表を提示する。OCR 結果と自分の読み取りが食い違う行は正直に書く

```text
| 番号 | 承認セリフ | OCR | 私の読み取り | 判定 |
| 01 | おはよう | おはよう | おはよう | 一致 |
| 03 | ありがとう | ありがどう | ありがとう（濁点が怪しい） | 要確認 |
```

3. 選択肢で聞く: 「全点正しい」「誤字あり（番号を教えてください）」。OCR の `mismatch` だけでは再生成せず「要確認」として、エージェントの実画像読取またはユーザー確認でも不一致になった番号だけを再生成する
4. 「全点正しい」で SESSION `text_check: ok`。実画像でも誤字ありと確認されたら該当番号だけ再生成し、`text-check` の版を上げて 2 からやり直す
5. OCR が使えない環境（exit 2）でも 2〜4 は省略しない

## セリフ案の出し方（P3）

- 日常の挨拶・返事・感情・リアクションを混ぜ、枚数分を表で提案する
- 各行: 番号 / セリフ / 表情 / ポーズ。01は決めポーズ、02〜04は使用頻度の高い挨拶と返事
- 文字なしの場合は「表情 / ポーズ / 伝えたい意味」を書く
- ユーザーの用途（家族用、店舗の常連向け、推し活など）が分かっていれば、それに合わせた語彙を優先する
- 商標、他サービス名、告知文（「◯月◯日発売」など）、誤字はこの段階で排除する

## 対話中に守ること

- 生成に失敗したら、失敗した旨と次の手（再生成／特徴ロックの修正）を1行で伝えてから再試行する
- 進捗は「P4 / 9」のように現在地を示す
- 長い説明より成果物を先に見せ、説明は後ろに短く付ける
- P3 は枚数分の案を先に表で示し、ユーザーが差し替え番号だけを答えられる形にする
