# 対話の進め方

## 原則

- 1ターンに1論点を基本とし、関連する選択は1回の構造化選択 UI に最大3問までまとめる
- 有限の選択肢で答えられる質問には構造化選択 UI を使う。推奨案を先頭に置き、短く相互排他的な選択肢と、選んだ場合の影響を示す
- 構造化選択 UI を利用できない環境だけ、推奨案を先頭にした番号付き選択肢へフォールバックする。特定製品のツール名は共通手順へ持ち込まない
- キャラクター名、slug、修正内容など、選択肢を限定できない質問は自由記述で聞く
- 回答を受けたら、その時点で確定した内容を3〜6行で復唱する。各 Phase の完了時は「完了した成果物」「次の Phase」「次に答える問い」を示し、承認は「承認 / 修正（箇所を記入）」のように回答形式まで明記する
- 曖昧な回答（「いい感じで」「おまかせ」）は、こちらの提案を1案だけ示して承認を取る。黙って決めない
- 承認語: 「OK」「続けて」「いいね」「それで」。差し戻し語: 「違う」「戻して」「もっと〜」。判別できなければ「承認として進めてよいですか」と確認する
- 差し戻しでは何が違うかを1問で特定し（顔・髪・服・ポーズ・文字のどれか）、該当ゲートだけをやり直す
- 生成画像は必ず「何を確認してほしいか」を添えて出す（例: 「前髪の分け目と目の大きさを見てください」）

## 実行フロー

1. `project --root . list` で進行中プロジェクトを確認し、続行・別プロジェクト・新規作成を構造化選択 UI で確定する
2. 新規なら実名でない slug の P0 プロジェクトを作り、素材をその `refs/` に隔離する
3. P0 前半で入力種別・枚数・文字の有無を、文字ありなら後半で文字方式・申請意図・候補数を確定する
4. キャラクター名などの自由記述を受け取り、P0 の確定内容を復唱して承認後に `confirm-p0` を実行する
5. P1〜P5 は各成果物を提示し、有限の採用・承認・差し戻し選択を構造化選択 UI で1ゲートずつ確定する。P1はチェックリストと数値・画像を版付きで固定し、変更時はP1へ戻る
6. P6 で `self-test` と `validate-pack` を実行し、検証済み ZIP を作成する
7. 公開する場合は P7 でメタ案と申告・参加設定を確定し、`check-publish-ready` 後に承認を得る
8. P8 はアカウント名・販売者ID・登録先の確認後に入力とプレビュー確認を支援し、定型文を表示して制作完了とする。審査リクエストと追跡は扱わない

`adult`、`consent`、`rights` は質問・保存・ゲート判定を行わない。`license_proof` は LINE から追加資料を求められ、ユーザーが提示した場合だけ任意情報として扱う。ユーザーが歴史上の人物を題材とすると明示した場合は、著作権・肖像権・パブリシティ権・本人許諾・ライセンス証明を確認対象外とする。

`text_mode: ai` を選択肢に出す前にTesseract本体・`pytesseract`・日本語データを診断する。利用不能なら、メインエージェントの目視と独立した画像認識を別々に実行して版付き証跡を作れるか確認する。どちらの自動経路もなければ `font` を推奨し、「フォント方式へ変更 / 自動検査環境を準備して続行を保留」の選択肢を出す。

## プロジェクト確定の質問テンプレ

制作依頼を受けたら P0 より前に確定する。`python scripts/line_stamp.py project --root . list` の結果に進行中があれば:

```text
進行中のプロジェクトがあります。どうしますか？
1. usagi（P4 / 16枚 / 未申請）を続ける
2. neko（P7 / 8枚 / メタ案待ち）を続ける
3. 新しいプロジェクトを作る
```

新規作成を選んだら、実名でない slug を確定して公開 CLI の `project ... new --slug <slug>` で P0 プロジェクトを作る。素材はその `refs/` に置き、P0 の全項目をユーザーが承認した後だけ `project ... confirm-p0` を実行する。`confirm-p0` が確定内容を SESSION へ保存し、P1 へ進める。

## P0 の質問テンプレ

```text
LINEスタンプの制作を始めます。3つ教えてください。
1. 元にする素材はどちらですか？
   A. 人物の写真（ちびキャラに変換します）
   B. 既存のキャラクター画像（そのデザインを踏襲します）
2. 枚数はいくつにしますか？ LINEの規定で 8 / 16 / 24 / 32 / 40 のいずれかです。初めてなら16をおすすめします。
3. スタンプに文字（セリフ）を入れますか？ 入れる / 入れない
```

文字を入れる場合は続けて方式を選択肢で聞く:

```text
文字の入れ方を選んでください。
A. 埋め込みフォント（おすすめ）— 承認したセリフから決定論的に描き、全点で同じ見た目にします。原文、欠字、可読性は確認一覧で目視します
B. 生成AIに描かせる — 手書き風など自由な表現ができます。ただし誤字や字の崩れが出やすいので、1点ずつ文字の検査と確認をはさみます
```

続けて、選択項目を構造化選択 UI で最大3問にまとめ、自由記述は別に聞く:

```text
4. キャラクターの呼び名を決めてください（申請時のタイトルにも使います。実名は避けます）
5. LINE Creators Market へ審査申請しますか？ する / しない（ローカル確認用の成果物まで。LINE 上では配布・利用できません）
6. 代表スタンプ（01）の候補を何枚出しますか？ 1 / 2 / 3（既定1）
```

## 各ゲートの提示と質問

| Gate | 提示するもの | 聞くこと |
|---|---|---|
| P1 | 髪形、数値の頭身、服装、HEX配色、目、固定装飾、背景透過、参考画像をまとめた版付きデザインシート | 「この仕様と画像で固定しますか。承認 / 修正（項目名）」 |
| P2 | 三面図1枚（正面・斜め・決めポーズ） | 「3つが同じキャラに見えますか。違和感は 顔 / 髪 / 服 / 体型 のどれですか」 |
| P3 | セリフ・表情・ポーズ表（agentが枚数分を提案） | 「差し替えたい番号と新しいセリフを教えてください。なければOKで確定」 |
| P4 | stamp01の候補と文字スタイル（`font`: フォント・色・縁取り／`ai`: 文字の雰囲気）。`ai` は 01 の文字検査結果 | 「採用する候補番号」「文字の色と縁取りはこのままで良いか」。`ai` は「読み取った文字は『◯◯』です。承認セリフと一致していますか」 |
| P5 | 全画像を1枚に載せた review-vNN.png（白背景と濃色背景）。`ai` は text-check-vNN.md、文字領域マスク、読み取り表 | 「承認 / 修正（番号）」で聞く。`ai` は先に「全点正しい / 誤字あり（番号）」で聞く |
| P6 | 検証ログとZIPのファイル一覧 | 質問なし。エラー0を報告してターンを終了し、P7 は次のターンで開始 |
| P7 | メタ案（日英タイトル・説明、クリエイター名、コピーライト、価格、3択の販売エリアと対象国、手動販売開始、LINE STORE 表示、AI/写真使用申告、プレミアム参加） | 「この内容で登録して良いですか。変更箇所があれば項目名で」 |
| P8 | 入力前のアカウント名・販売者ID・登録先と、入力後のサマリ・プレビュー結果 | 最初に「このアカウントと登録先で進む / 別アカウントへ切り替える / P8を中止する」。完了後は「制作が完了しました。問題なければ審査リクエストを実施してください。」と表示して終了 |

## 文字検査の出し方（`text_mode: ai` のみ、P4 と P5）

1. 公開 CLI の `verify-text` を実行し `review/text-check-vNN.md` と `text-masks/vNN/` を作る。Tesseractが使えない場合は独立した画像認識モデルの版付きJSONを `--vision-evidence` で渡す。どちらも使えない場合はここで停止する
2. 自動検査とは別に、エージェント自身が各画像を開いて文字を読み、次の表を提示する。自動結果と自分の読み取りが食い違う行は正直に書く

```text
| 番号 | 承認セリフ | 自動検査 | 私の読み取り | 判定 |
| 01 | おはよう | おはよう | おはよう | 一致 |
| 03 | ありがとう | ありがどう | ありがとう（濁点が怪しい） | 要確認 |
```

3. 選択肢で聞く: 「全点正しい」「誤字あり（番号を教えてください）」。自動検査の `mismatch` だけでは再生成せず「要確認」とし、実画像またはユーザー確認でも不一致になった番号だけを再生成する
4. 「全点正しい」で SESSION `text_check: ok` と最新の `text_mask_version` を記録する。誤字ありなら該当番号だけ再生成し、検査版を上げて 2 からやり直す

## セリフ案の出し方（P3）

- 日常の挨拶・返事・感情・リアクションを混ぜ、枚数分を表で提案する
- 各行: 番号 / セリフ / 表情 / ポーズ。01は決めポーズ、02〜04は使用頻度の高い挨拶と返事
- 文字なしの場合は「表情 / ポーズ / 伝えたい意味」を書く
- ユーザーの用途（家族用、店舗の常連向け、推し活など）が分かっていれば、それに合わせた語彙を優先する
- 商標、他サービス名、告知文（「◯月◯日発売」など）、誤字はこの段階で排除する

## 対話中に守ること

- 生成に失敗したら、失敗した旨と次の手（再生成／特徴ロックの修正）を1行で伝えてから再試行する
- 進捗は「現在 P4 / 最終 P8」のように現在地を示す
- 長い説明より成果物を先に見せ、説明は後ろに短く付ける
- P3 は枚数分の案を先に表で示し、ユーザーが差し替え番号だけを答えられる形にする
